# Confirmation Gate — 确认门

在关键决策点暂停并请用户确认，是防止"输出与预期不符"的最有效机制。

## 何时启用确认门

### 必须启用（高代价决策）
- 完整章节写作前的框架确认
- 引用匹配策略确认（特别是低置信度匹配）
- 格式配置确认（模板分析结果 vs 用户口述要求）
- 多篇文献的角色分类结果（特别是 LLM 辅助分类的部分）

### 可以跳过（低代价决策）
- 单段落润色
- 明确的术语修正
- 已确认框架内的填充式写作
- 用户明确说"直接做，不用确认"

## 确认门输出格式

```
## 确认要点

**核心参数**:
- 任务: [写作/润色/引用/审稿]
- 目标章节: [引言/方法/讨论/...]
- 格式: [GB/T 7714 / APA 7 / ...]
- 语言: [中文/英文]

**关键决策**:
1. [决策点1]: [当前选择] — [为什么这样选]
2. [决策点2]: [当前选择] — [为什么这样选]

**需确认的问题** (最多2-3个，只问真正有歧义的):
- [问题1]
- [问题2]
```

## 确认门的核心原则

1. **只在真正有歧义时询问** — 不要为了凑数而提问
2. **展示推理过程** — 让用户看到"为什么这样选"，而不只是"选了什么"
3. **尊重用户时间** — 一个5秒能扫完的确认块，远好于一个需要仔细研究的确认块

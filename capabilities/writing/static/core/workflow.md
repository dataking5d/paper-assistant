# Writing Workflow — 写作工作流

按以下6步执行任何写作或重构任务。

## 1. 构建一句话论点

> 在 [系统/问题] 中，我们通过 [方法] 展示了 [发现]，以 [证据] 为支撑，边界是 [局限]。

让每个章节都为这句话服务。如果写不出这句话，说明论文还没有清晰的论点——向用户指出这一点。

## 1b. 建立术语账本

首次接触材料时，提取所有重复出现的领域术语进入术语账本。锁定规范形式，在所有章节中复用。详见 `capabilities/_shared/terminology-ledger.md`。

## 2. 选择章节架构

从对应的 `section/*.md` 片段中选取章节结构。

## 3. 每个段落分配一个任务

每个段落只做以下任务中的一项：context（背景）、gap（缺口）、approach（方法）、result（结果）、comparison（比较）、mechanism（机制）、implication（含义）、limitation（局限）。

## 3b. 确认门 — 先对齐再写

在写完整章节之前，先展示对齐块并停止等待确认：

- **一句话论点**（来自步骤1）
- **段落计划**：章节架构 + 每个段落的单一任务
- **关键术语**：术语账本中的规范形式
- **假设**：你推断但未被明确告知的所有内容，标记为假设
- 最多**2-3个关键问题**，只问真正有歧义的选择

跳过确认门的条件：核心主张、证据和边界都清晰给出，没有真正的歧义。

## 4. 从证据向外写

保持观点紧贴支撑证据。不要在章节顶部堆满观点而把证据留在底部。

## 5. 动词对齐证据强度

- `证明/揭示` → 需要强有力的直接证据
- `表明/暗示` → 趋势级或间接证据
- `可能/也许` → 合理但未经验证的机制

## 6. 输出散文 + 注释

输出草稿的同时附上假设说明、缺失输入和需要补充证据的位置。
